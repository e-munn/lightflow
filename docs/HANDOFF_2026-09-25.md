## Pose-quality findings and continuation

Read [the detailed report](../research/dance/POSE_QUALITY_2026-09-23.md).
All candidates processed byte-identical preview/audio files with matching frame
timestamps and the same strict solo policy. Existing run hashes were verified
unchanged. The default extractor remains MediaPipe Full.

| Passage | Full usable body frames | Heavy | RTMW |
| --- | ---: | ---: | ---: |
| Crave You | 60.3% | 43.8% | 93.7% |
| Beat Killer | 99.6% | 98.2% | 100.0% |
| Feel the Way I Feel | 87.8% | 77.7% | 100.0% |

These are 12-joint confidence/in-frame coverage rates, **not positional
accuracy**. RTMW and MediaPipe confidence scores are not calibrated to each
other. Sampled overlays show plausible recovered wrists/elbows with RTMW, but
RTMW also makes furniture detections in Crave You: 114 frames become unassigned
under the strict solo policy. Missing observations are not stillness or darkness.

RTMW preserves native 133-point 2D data and maps exact compatible joints into
the existing 33-slot format. Unmapped points have zero confidence; `z=0` is a
placeholder, not estimated depth. It has no explicit temporal consistency or
occlusion-recovery stage. Finger precision and jitter are not yet quantitatively
validated. The comparison intentionally disables display smoothing.

New RTMW runs (in `runs/`):

- Crave You: `36b62e47-8674-4d6a-ae9a-81b583272ee4`
- Beat Killer: `994e2632-1d2f-4392-a841-93368c8335a0`
- Feel the Way I Feel: `058e91bb-67d2-4970-b0d5-bdb06b541d4b`

CoreML extraction took about 37–95 seconds per 30-second excerpt, excluding
model startup. CPU/CoreML parity was checked on 480 shared frames. The native
runtime crashed at interpreter teardown after a successful standalone test;
the isolated successful CoreML worker flushes outputs and uses `os._exit(0)` to
avoid that finalizer. This is an offline workaround, not live-service readiness.

Useful next extraction work: distinguish the dancer from false detections with
reviewed subject-region/association logic; validate on true multi-person cases,
manually check joint placement on fixed frames, then measure temporal jitter.
Preserve gaps and references. A larger dataset should follow quality evidence.

## Realistic 3D scene specification

`research/dance/realistic-light-scene.ts` records the latest requested design:
dark textured floor, wooden podium, two floor moving-heads, two inward-facing
LED panels, warm amber light, subtle haze, feathered beams, soft shadows,
restrained bloom and reflections. A fixed-exposure camera fills the viewport.
All fixtures share **one brightness input**, with fixed relative power.

This file describes intended rendering behavior. Volumetric scattering,
reflections, richer materials and shadows are **not implemented by this spec**.
Existing `src/components/Rig3D.tsx` provides the older basic rig. Building the
realism upgrade should preserve the brightness envelope and expose the same
one-channel signal without adding independent fixture choreography.
